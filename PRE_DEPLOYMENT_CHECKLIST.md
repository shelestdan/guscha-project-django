# ✅ Checklist перед деплоем в Production

## 🔐 Безопасность

### Критически важно:
- [ ] **SECRET_KEY** изменён на уникальный (не содержит "django-insecure")
- [ ] **JWT_SECRET_KEY** изменён и отличается от SECRET_KEY
- [ ] **ADMIN_URL** изменён на секретный путь (не "admin/")
- [ ] **POSTGRES_PASSWORD** - сильный пароль (минимум 20 символов)
- [ ] **DEBUG=False** в .env файле
- [ ] **.env файл НЕ закоммичен** в git (проверьте: `git status`)
- [ ] **ALLOWED_HOSTS** содержит только ваш домен
- [ ] **CORS_ALLOWED_ORIGINS** содержит только ваш домен

### Рекомендуется:
- [ ] Настроен **ADMIN_IP_WHITELIST** (если нужно ограничить доступ)
- [ ] Настроены **email уведомления** (ADMINS, EMAIL_HOST_*)
- [ ] Настроен **HTTPS/SSL** сертификат
- [ ] Настроен **firewall** на сервере
- [ ] Включена **двухфакторная аутентификация** для админов

---

## 📦 Конфигурация

### Обязательно:
- [ ] **DOMAIN_NAME** указан правильно
- [ ] **FRONTEND_URL** указан с https://
- [ ] **TELEGRAM_BOT_TOKEN** получен от @BotFather
- [ ] **TELEGRAM_BOT_USERNAME** указан правильно
- [ ] **POSTGRES_DB** имя базы данных для продакшена

- [ ] **NGROK_AUTHTOKEN** (только для разработки)

## 🚀 Финальная проверка

### Запустите скрипт проверки:
```bash
./check-deployment.sh
```

### Проверьте вручную:
1. Откройте сайт в браузере
2. Зарегистрируйте тестового пользователя
3. Добавьте товар в корзину
4. Оформите заказ
5. Проверьте админку
6. Проверьте Telegram бота

### Проверьте логи:
```bash
docker compose logs --tail=100
```

### Проверьте безопасность:
```bash
# Проверьте что .env не в git
git status | grep .env

# Проверьте что DEBUG=False
grep DEBUG guscha_django/.env

# Проверьте что SECRET_KEY изменён
grep SECRET_KEY guscha_django/.env | grep -v "django-insecure"
```

## 📞 Что делать после деплоя?

1. **Мониторьте логи** первые 24 часа
2. **Проверяйте метрики** производительности
3. **Следите за ошибками** в логах безопасности
4. **Делайте бэкапы** регулярно
5. **Обновляйте зависимости** раз в месяц

---

## 🆘 Если что-то пошло не так

1. Проверьте логи: `docker compose logs`
2. Проверьте статус: `docker compose ps`
3. Откатитесь к предыдущей версии: `git checkout <previous-commit>`
4. Восстановите из бэкапа
5. Обратитесь к [DEPLOYMENT_GUIDE.md](DEPLOYMENT_GUIDE.md)
